前言：这本附录怎么用

学完十九卷正卷后，你会接触大量名词——从 Transformer 到 MCP，从 KV Cache 到 FinOps。本卷把这些术语与工具浓缩成三张速查表，解决"读到某卷想不起某词含义"的回查需求。它不是教学卷，而是一本"随时翻"的手册：遇到不懂的词先来查一句话释义，需要选工具时来看工具地图，想深入某个方向时看推荐资源。

使用建议：第一次阅读时跳过本卷（它会在正卷中反复出现）；学完某一阶段后回来看对应条目检验掌握度；做技术方案或写文档需要术语表时直接引用。本卷刻意保持条目式写法，不展开论述——展开的内容都在对应卷次。

全书综合面试自测（附参考答案）

本节是全书十九卷正卷的收官自测：十二道跨卷综合题按由浅入深排列，覆盖认知原理、选型部署、检索记忆、规划协作、运维安全与端到端设计，模拟一场资深 Agent 工程师的终极面试。每题题末以全角括号标注主要来源卷，参考答案先给一句话结论，再以要点展开，方便快速对照。建议先自行作答或口述框架，再核对答案查漏补缺；答不上来的题目，按标注卷次回读对应章节。

题1　什么是 Agent？它与聊天机器人、工作流的本质区别是什么？（卷01）

结论：Agent 是以大语言模型为核心控制器，能够感知环境、自主规划、调用工具、持续记忆并在反馈中修正行为，最终完成给定目标的软件系统。它与聊天机器人的分野在于为完成任务负责：聊天机器人止于对话，工作流的执行路径由开发者预先写死，而 Agent 的执行路径由模型在运行时自主决定。工程上两者并非对立，成熟系统常用工作流的骨架加 Agent 的关节：确定性环节走固定流程，依赖语义判断的子任务交给 Agent。

题2　从注意力到记忆："上下文窗口有限"这一个底层约束，催生了哪几套技术？（卷02/卷07/卷11）

结论：同一个约束在不同技术层催生了三套互补技术，本质都是把有限的上下文预算花在最值钱的信息上。

  • 推理层：KV Cache 与 PagedAttention、前缀缓存，让窗口装得下、算得快（卷02/卷05）
  • 交互层：上下文预算分配与压缩、隔离两大策略，对冲中段遗忘（卷07）
  • 知识层：RAG 与向量检索，只把最相关的外部知识注入窗口（卷08/卷09）
  • 记忆层：滑动窗口、摘要压缩加长期记忆，让历史跨会话续接（卷11）

题3　什么时候用普通指令模型，什么时候用推理模型？思考预算如何权衡？（卷04）

结论：推理模型以强化学习训练出内部推理链，把测试时计算变成质量来源，适合数学、代码、规划类多步严谨推理；对话、分类、抽取等任务用普通指令模型即可。思考预算（reasoning_effort 类参数）控制模型花多少 Token 思考：预算越高正确率通常越高，但延迟与成本成倍增长。它与稠密或 MoE 的架构选择相互正交，生产上应让关键路径用推理模型、简单子任务路由到普通或小模型。

题4　自部署一个开源模型，如何用推理引擎与压缩技术做到跑得快、跑得省？（卷05/卷06）

结论：吞吐靠推理引擎三件套，成本靠以 4-bit 为主的量化方案，两者共同决定最终的单位 Token 成本。

  • PagedAttention 分页管理 KV Cache，显存利用率约 95%；Continuous Batching 让 GPU 动态满员（卷05）
  • Prefix Caching 复用相同前缀，对多轮 Agent 的延迟与成本收益最大（卷05）
  • INT4 是甜点区：70B 模型从约 140GB 降到约 35GB，保留 97% 到 99% 能力（卷06）
  • 自部署 vLLM 配 AWQ，本地实验用 Ollama 跑 GGUF；关注 TTFT 与 TPOT 指标（卷05/卷06）

题5　提示工程、RAG、微调、记忆系统，分别解决什么问题、什么时候选用？（卷07/卷08/卷11）

结论：四者作用于不同层：提示工程写清任务指令，RAG 注入会变化的知识，微调塑造稳定的行为风格，记忆系统沉淀跨会话的用户状态。

  • 明天就要更新的知识用 RAG：可溯源、可回滚、更新知识库即时生效（卷08）
  • 一年不变且写不进提示词的风格、格式与术语习惯，才考虑微调（卷08）
  • 用户偏好、历史决策等跨会话状态进长期记忆：向量管召回、图管关系（卷11）
  • 拿不准时先做 RAG：见效快、可评估；把微调当知识库用是危险的半真相（卷08）

题6　一个 RAG 系统答案不准，如何按链路归因？检索质量有哪些标准优化手段？（卷08/卷09）

结论：按解析、切分、嵌入、检索、重排、生成全链路归因，多数瓶颈出在解析与切分环节，而不是生成模型本身。

  • 切分用递归或父子分块：小块定位、父块提供上下文，检索准与上下文全兼得（卷08）
  • 混合检索双通道：向量管语义泛化、BM25 管精确锁定，RRF 按排名倒数融合（卷08/卷09）
  • 交叉编码器重排做精加工，把 Top-5 相关率从约三成抬到八成以上（卷08）
  • 辅以查询改写与 HyDE 提升召回；资料中没有的必须拒答，不得编造（卷08）

题7　Function Calling 与 MCP 是什么关系？MCP 为什么能终结 M×N 集成地狱？（卷10）

结论：Function Calling 是模型输出结构化工具调用指令的基础能力，MCP 是统一工具接入的开放协议：任何工具实现一次 MCP Server，就能被任何支持的模型与客户端使用，M 个模型对接 N 个工具的集成矩阵由此坍缩为 M+N。

  • 工具描述四要素：name、description、parameters、required，质量决定调用准确率（卷10）
  • MCP 三大原语 Tool、Resource、Prompt 各司其职（卷10）
  • Structured Outputs 用受限解码保证输出必然符合 Schema，结构错误近零（卷10）
  • 工具数量与选择准确率近似对数下降，需按场景分组或用子 Agent 分治（卷10）

题8　设计一个生产级记忆系统：短期与长期如何分工？Checkpoint 与 HITL 各解决什么？（卷11）

结论：采用分层架构——短期记忆是会话内的工作台，长期记忆是跨会话的档案室，Checkpointer 负责状态快照、断点恢复与人工介入。

  • 短期用滑动窗口加摘要压缩，做 Token 预算分配；系统提示与当前消息永不裁剪（卷11）
  • 长期走提取、向量化、存储、检索、注入五步管线，写入需重要性评分与去重（卷11）
  • Checkpoint 支持断点恢复与时间旅行，interrupt 挂起实现 HITL 人工审批（卷11）
  • 检索必须强制 user_id 过滤防跨用户泄露，配 PII 过滤与被遗忘权删除接口（卷11）

题9　ReAct、Plan-and-Solve、ReWOO、Reflexion 各解决什么问题？如何选型并防止循环失控？（卷12）

结论：按任务三特征选型——环境多变选 ReAct，流程稳定选计划式，成本敏感且步骤可提前声明选 ReWOO，存在确定性评估信号才用 Reflexion。

  • ReAct 思考、行动、观察交错，观察接地抑制幻觉，是 Agent 基础骨架（卷12）
  • ReWOO 把计划、执行、求解解耦，观察不回灌上下文，Token 大降且可并行（卷12）
  • Reflexion 三角色闭环把失败写成教训存入记忆；评估器不可靠会导致反思中毒（卷12）
  • 步数、预算、时间三道上限熔断：上限内的失败是可预算的失败（卷12）

题10　什么时候该把单 Agent 升级为多智能体？协作模式如何选？跨组织如何互联？（卷13/卷14）

结论：当单 Agent 上下文装不下、单点失败无法在传播途中拦截时才组队；但失败率随 Agent 数量近似指数增长，三到七个是收益与复杂度的平衡区间。

  • 监督者模式只做路由、聚合、兜底，职责分离最可控，且必须配兜底 Agent（卷13）
  • 对等网络、层次化、状态机各有适用边界，真实系统常混搭成混合架构（卷13）
  • LangGraph 以状态图、条件边、检查点成为复杂编排的主流选择（卷13）
  • 跨组织互联用 A2A：Agent Card 声明能力、Task 跟踪状态，与 MCP 互补分工（卷14）

题11　Agent 上线后用户投诉答非所问，如何用可观测与评估体系定位问题并守住质量？（卷15）

结论：先用全链路追踪把一次任务完整回放、定位到具体环节，再用评估金字塔把修复固化为回归防线，最后靠 SLO 持续守住质量底线。

  • Trace 与 Span 把几十次模型、工具调用串成可回放轨迹，精确定位坏在哪一环（卷15）
  • 评估金字塔四层：单元、离线、在线、人工；评估左移，接入 PR 门禁（卷15）
  • LLM-as-a-Judge 可自动评分，但须校准位置、长度、自我偏好等偏差（卷15）
  • 用 SLI、SLO 与 RED 方法设定质量与延迟目标，指标异常触发告警与回滚（卷15）

题12　终极设计题：从零设计一个生产级电商客服 Agent 的完整技术栈，你会怎么选型与落地？（卷19）

结论：按六层技术栈自上而下落位，用工作流的骨架加 Agent 的关节组织流程，并把安全、成本与评估内建为设计的一部分；多模态可作为语音与识图客服的能力扩展（卷17）。

  • 模型与成本：意图分层路由，复杂任务用旗舰或推理模型、简单任务用小模型，叠加语义缓存与前缀缓存（卷04/卷18）
  • 增强层：RAG 混合检索加重排与拒答，工具统一走 MCP，退款等不可逆动作设 HITL 审批点（卷08/卷10/卷11）
  • 编排与交互：状态图编排加 Checkpointer 断点续聊，SSE 流式输出实时呈现进度（卷13/卷14）
  • 运维层：纵深防御防提示注入、最小权限，灰度发布小流量验证，Trace 加黄金评估集持续回归（卷15/卷16）
